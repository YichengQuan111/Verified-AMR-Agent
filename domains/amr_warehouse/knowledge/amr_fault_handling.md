# AMR 与仓储执行异常处理规范

> 本文档冻结 P0-15 的异常分类与恢复原则。  
> 必须覆盖：低电量、AMR 离线、通道封闭、工位占用、工具超时、计划不可行和状态冲突。

## 1. 总原则

异常发生后按顺序确定：

1. 真实 Observation。
2. 受影响实体。
3. 受影响的未完成 DAG 子图。
4. 已经产生的副作用。
5. 当前计划是否仍合法。
6. 应采用 `retry / replan / fallback / human / fatal` 中哪种处置。
7. 是否达到步骤、时长、Token 或重规划预算。

P0 默认最多 **2 次局部重规划**。

## 2. 错误分类

| 异常 | 默认动作 |
|---|---|
| 低电量 | 重新验证电量；充电、局部重规划或 human |
| AMR 离线 | 查询真实状态，失效相关未完成节点并局部重规划 |
| 通道封闭 | 失效引用封闭区域的未完成路径并重新规划 |
| 工位占用 | 在预算内等待/调整/重规划，超预算后 fallback/human |
| 工具超时 | 先查真实状态与 Effect Ledger，再判断 retry |
| 计划不可行 | 重新分配/排序/路径重规划，预算耗尽后升级 |
| 状态冲突 | 以最新可信 Observation 为准，必要时 human |

## 3. 低电量

冻结阈值：

- warning 30%
- charge 20%
- critical 10%
- safety reserve 15%
- full 90%

规则：

- `20% < battery ≤30%`：预警，增加 `battery_risk`。
- `10% < battery ≤20%`：触发充电调度，不再接受普通新任务。
- `battery ≤10%`：禁止继续普通运输。
- 预计完成后 `<15%`：计划不可行。

若已经取货：

- `10% < battery ≤20%` 且当前交付仍可验证为“完成后 ≥15%”，允许只完成当前已取货订单。
- 否则进入安全保持、重规划或人工处理。
- `battery ≤10%` 且仍载货时进入人工处理；P0 不做跨 AMR 物料转移或带货充电。

## 4. AMR 离线

1. 标记该 AMR 不可正常调度。
2. 获取最后可信状态。
3. 找出引用该 AMR 的未完成节点。
4. 保留已完成节点和 Effect Ledger。
5. 失效受影响未完成节点。
6. 重新分配或局部重规划。
7. 新计划重新验证。

若 AMR 已载货且真实物料状态无法确认，进入 `human`，不能自动假设物料位置。

## 5. 通道封闭

- 引用封闭单元格/边的未完成路径立即失效。
- 已完成节点不回滚。
- 只重规划受影响子图。
- 新计划必须重新通过路径与车队 Validator。
- 无安全可行路径时进入 Fallback/human/fatal。

P0 Agent 不负责解除禁行区或修改单向规则。

## 6. 工位占用

- 不假设工位会立即释放。
- 在运行预算内可等待。
- 可调整尚未执行的任务或局部重规划。
- 超过预算后停止自动循环并升级。

P0 不定义“自动改投任意其他工位”；若目标工位不可替代且长期不可用，进入 human/fatal。

## 7. 工具超时

工具超时不等于成功或失败。

对于有副作用工具：

1. 使用 `run_id + plan_version + task_id` 查询 Effect Ledger。
2. 查询仿真器/外部真实状态。
3. 若确认尚未执行，才允许在工具重试预算内重试。
4. 若已经执行，则禁止重复执行。
5. 状态仍不确定时进入 `human`。

## 8. 计划不可行

Validator 判定不可行时：

- 不修改硬约束。
- 可更换 AMR。
- 可调整未执行任务顺序。
- 可重新规划路径。
- 可局部替换受影响 DAG。

最多 2 次局部重规划；仍不可行则进入 Fallback、human 或 fatal。

## 9. 状态冲突

典型冲突：

- Checkpoint 与当前仿真状态不同。
- Agent 任务状态与工具结果不同。
- 旧地图版本与当前环境不同。
- LLM 声称完成，但 Observation 未完成。

原则：

- 以最新、可验证、带来源和版本的 Observation 为准。
- LLM 文本不能覆盖工具事实。
- 若两个同等级可信数据源仍无法裁决，进入 `human`。

## 10. Checkpoint 与恢复

恢复时必须：

- 读取 PostgreSQL Checkpoint。
- 查询关键真实状态。
- 检查 Effect Ledger。
- 保留已完成节点。
- 不重复已完成副作用。
- 只恢复未完成且仍合法的部分。

P0 硬目标：重复副作用次数为 0。

## 11. Fallback 与 Fatal

Fallback 可包括：

- 停止继续派发。
- 保留已完成结果。
- 返回明确不可行原因。
- 等待外部状态恢复。
- 请求 operator 处理。

进入 fatal 的典型条件：

- 达到总时长/步骤预算。
- 达到 2 次局部重规划上限。
- 无安全可行方案。
- 关键工具持续不可用且无安全 Fallback。
- 继续执行必然违反硬约束。

## 12. 禁止事项

- 无限重试。
- 无限重规划。
- 超时后盲目重复副作用。
- 绕过 Validator。
- 使用旧状态强行继续执行。
- 为完成任务修改硬安全约束。
- 状态不确定时标记成功。
- LLM 自行创造新的故障规则。
- 未经受控审批执行人工接管。
