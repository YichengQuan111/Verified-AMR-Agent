# 仓库交通与通道管理规则

> 本文档冻结 P0 的交通与路径约束：二维栅格、单向/窄通道、临时禁行区、顶点冲突、交换边冲突、安全距离、A* 与时空预约表。

## 1. 适用范围

适用于 4 台 AMR 在 30×20 栅格仓库中的离散路径规划与仿真执行。

交通规则属于硬约束；LLM、任务优先级和人工审批都不能直接绕过。

## 2. 路径状态与动作

A* 状态：

- `x`
- `y`
- `heading`
- `t`

动作至少包括：

- 前进。
- 转向。
- 等待。

代价包含移动、转向和等待；启发式使用曼哈顿距离。

## 3. 固定障碍与边界

路径必须：

- 不越出地图边界。
- 不进入固定障碍/货架不可通行单元。
- 起点或终点非法时直接返回输入错误或不可行。

不得由 LLM 自动修改非法坐标。

## 4. 单向通道

对地图标记为单向的边/通道：

- 只能沿允许方向通过。
- 逆向通行非法。
- 高优先级订单不能突破单向约束。
- 若合法方向无可行路径，则等待、重规划或返回不可行。

P0 Agent 不提供“临时反转单向规则”的工具。

## 5. 窄通道与规划顺序

窄通道仍需满足时空预约约束。

当多车竞争同一受限区域时，规划顺序按：

1. 订单优先级。
2. 发布时间 `release_time`。
3. 稳定的订单/AMR 标识作为最终确定性 tie-break。

这样保证相同输入可复现，不需要 LLM 临时发明“谁先走”的规则。

## 6. 临时禁行区

临时禁行区一旦出现在当前地图/环境版本中：

- 新路径不得进入。
- 引用该区域的未完成旧路径失效。
- Verifier 识别受影响 AMR 与未完成子任务。
- Replanner 只替换受影响子图。
- 新计划必须重新通过 Validator。

**P0 Agent 不提供解除禁行区的写工具。**  
若外部环境合法更新了禁行区状态，系统应获取新的环境版本后再规划；不能对旧版本做口头豁免。

## 7. 顶点冲突

顶点冲突：两台 AMR 在同一时间占用同一栅格。

P0 要求：

- 使用 `(cell, t)` 预约避免。
- Validator 派发前再次检查。
- 冲突次数目标为 0。

含顶点冲突的计划必须拒绝。

## 8. 交换边冲突

交换边冲突：两台 AMR 在同一时间沿同一条边相向交换位置。

P0 要求：

- 使用 `(edge, t)` 预约阻止。
- 冲突次数目标为 0。
- 失败时等待、调整规划顺序、重规划或返回不可行。

## 9. 安全距离

`fleet_plan_validator` 必须检查安全距离。

具体数值由运行配置/Validator 提供，RAG 文档不写死数值。若执行时缺失该必要配置，应判定配置错误，不允许模型猜测。

## 10. 等待与重新规划

等待是合法动作，但：

- 受任务/运行总时长和步骤预算约束。
- 不允许无限等待。
- 环境变化导致旧计划失效时，应局部重规划。
- P0 默认最多 2 次局部重规划。

## 11. 交通规则变化后的流程

1. 获取最新地图/环境 Observation。
2. 标记受影响未完成路径和任务。
3. 保留已完成节点与 Effect Ledger。
4. 计划版本加一。
5. 局部重规划。
6. 重新执行确定性验证。
7. 验证通过后才继续派发。

## 12. 禁止事项

- 穿越障碍物。
- 进入当前生效的禁行区。
- 逆行通过单向通道。
- 派发存在顶点冲突的计划。
- 派发存在交换边冲突的计划。
- 为缩短路线绕过安全距离检查。
- 让 LLM 自行创造交通优先权。
- 通过审批把非法路径直接变合法。
- 无限等待或无限重规划。
- 通过 Agent 修改禁行区或单向规则。
