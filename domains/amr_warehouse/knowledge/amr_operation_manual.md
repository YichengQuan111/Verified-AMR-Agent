# AMR 运行与状态说明手册

> 本文档是 P0-07 设备知识的冻结基线。  
> P0 固定使用 4 台同构差速驱动 AMR。AMR 是受控 Agent 的作业编排对象，不是 4 个 LLM Agent。

## 1. 职责边界

- LLM Agent：理解目标、生成结构化计划、选择工具和提出异常处置建议。
- C++ 模块：任务分配、路径规划和车队计划验证。
- Python 仿真器：推进 AMR、订单、工位、充电站和故障状态。
- P0 不包含真实底盘、定位、SLAM、感知和电机控制。

## 2. AMR 关键状态字段

每台 AMR 至少保存：

- `position`
- `heading`
- `battery`
- `load`
- `task_status`
- `health_status`
- `connection_status`

所有安全关键决策必须使用最新、带来源/版本的状态快照。

## 3. P0 任务状态机

### `IDLE`
没有正在执行的运输或充电任务。是否可接受新任务仍需结合电量、健康、连接、载荷与业务约束判断。

### `TO_PICKUP`
正在前往取货点。

### `LOADING`
已经到达取货点，正在执行装载阶段。

### `TO_DROPOFF`
已完成取货，正在前往交付点。该阶段已经产生取货副作用，恢复时不得把订单当成“尚未取货”。

### `UNLOADING`
已经到达交付点，正在执行卸载/交付。

### `TO_CHARGE`
正在前往充电站。电量 `≤20%` 时触发充电调度；是否立刻转入该状态仍需结合当前任务阶段与验证结果。

### `CHARGING`
正在充电。达到 `≥90%` 视为 P0 首版充电完成。

### `OFFLINE`
车辆当前不可正常连接/调度。不得向其分配新的普通运输任务。

## 4. 状态变化原则

AMR 状态由仿真器/执行环境推进，不由 LLM 直接修改。

状态变化必须：

- 与已验证计划一致。
- 与时间推进一致。
- 与订单和工位状态一致。
- 可通过事件日志复核。
- 在相同地图、订单和随机种子下可复现。

## 5. AMR 可分配性

是否可分配不能只看 `IDLE`，至少检查：

- 连接状态。
- 健康状态。
- 电量。
- 载荷。
- 当前任务。
- 到取货点距离。
- 迟到风险。
- 任务载荷与其他业务约束。

不可行的 AMR—订单组合必须显式返回原因。

## 6. 电量冻结规则

- 预警阈值：`30%`
- 充电调度阈值：`20%`
- 危险阈值：`10%`
- 任务完成后最小安全余量：`15%`
- 充电完成阈值：`90%`

边界值按 `≤30% / ≤20% / ≤10%` 处理；任务预计完成后必须 `≥15%`。

## 7. 离线与健康异常

AMR 离线时：

- 不再视为可正常调度资源。
- 找出引用该 AMR 的未完成子任务。
- 保留已完成任务和 Effect Ledger。
- 先获取最新真实状态，再决定重规划、Fallback 或人工处理。
- 不得通过 Prompt 要求 Validator 忽略离线状态。

`health_status` 的具体枚举和值由 `AMRState` 数据契约定义；RAG 文档不另行创造枚举。

## 8. 路径执行异常

以下变化可能使旧路径失效：

- 临时禁行区出现。
- 通道封闭。
- 其他 AMR 时空预约变化。
- 当前 AMR 离线。
- 工位不可用。
- 工具/仿真状态与预期不一致。

必须由 Verifier 根据真实 Observation 判断旧计划是否仍合法。

## 9. 不在 RAG 中固定的设备参数

以下参数由运行配置或数据契约提供，知识库不写死数值：

- 最大载荷。
- 标称速度。
- 单步移动能耗。
- 转向耗时/能耗。
- 装载持续时间。
- 卸载持续时间。
- 充电速度。

当问题要求这些具体数值而当前 Observation/运行配置未提供时，应回答“当前知识库未规定”，不能猜测。

## 10. 禁止事项

- 仅根据 LLM 文本判断真实 AMR 状态。
- 向 `OFFLINE` AMR 派发普通新任务。
- 绕过计划验证器。
- 忽略禁行区或冲突检查。
- 让模型生成代码直接控制 AMR。
- 将故障注入能力暴露给正常 Agent。
- 恢复时重复已完成副作用。
